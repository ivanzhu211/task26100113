# attribution

营销收入的时间衰减归因库（Go）。上层一次性载入触点与转化事件（全部保存在内存、不再修改），随后可按日期范围查询归因汇总。无接口层、无外部依赖。

## 用法

```go
eng := attribution.New()
eng.Load(touchpoints, conversions) // []attribution.Touchpoint / []attribution.Conversion
sum := eng.Summarize(start, end)   // [start, end)，按转化时间筛选，UTC 秒
// sum.Groups: 各 渠道+活动 组合的归因金额（小数分）
// sum.Unattributed: 未归因金额（小数分）
```

## 业务规则实现

- 合格窗口：转化时间往前 2592000 秒至转化当秒，两端包含；同秒触点全部参与。
- 权重：2^(-Δt/604800)，7 天半衰期；按权重占比分配转化收入。
- 无合格触点的转化，全部收入计入未归因。
- 查询范围含起点、不含终点，按转化时间筛选；起点之前的触点只要落入所选转化的窗口仍参与分配。
- 金额为小数分，不提前舍入。

## 算法与复杂度

关键观察：2^(-(T-t)/H) = 2^(t/H) · 2^(-T/H)，比值分配中公共因子可约去，因此：

1. 载入时（`sweep.go`）：每个客户内按时间滑动窗口，均摊 O(1) 算出每笔转化的合格触点权重和 W，记录 B = R/W 与未归因前缀和。
2. 查询时（`query.go`）：交换求和次序——每个触点对 [t, t+L] 内的转化贡献 B·2^(-(T-t)/H)。触点与转化各自有序，双指针滑动窗口均摊 O(1) 累计到各组合。

总复杂度 O((n+m) log(n+m))（排序主导），查询 O(n+m)。单客户 20 万触点 + 20 万转化 + 10 万组合下，实测载入加一次全量汇总约 50ms、驻留堆内存约 44MiB。

## 数值精度

滑动窗口的和以「懒基准时间」表示（w_rel = 2^(-(tRef-t)/H)），基准仅在新事件超出当前基准一个窗口以上时才重置，使所有指数约束在 ±2·2592000/604800 内：20 年跨度与 10 年空档不会溢出，也不会丢失有效权重。实测 10 万组合的分组金额与逐笔展开的参考实现最大偏差约 1e-13 分，远严于 0.0001 元（0.01 分）的验收容差；收入守恒（已归因+未归因=范围内收入总额）偏差远小于 0.001 元。

## 测试

```sh
go test ./...
```

- `attribution_test.go`：乱序输入下多次转化共享触点、报告范围切割与 30 天窗口边界、跨多年空档后重新触达与转化、同秒触点、未归因、交错过期路径、随机对照；均与逐笔展开的参考实现比对并校验收入守恒。
